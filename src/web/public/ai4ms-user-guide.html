AI for Management Science · Product manual

把科研过程变成可协作、可审批、可复现的工作流。

AI4MS 面向管理科学研究者，把选题、已有研究报告、理论、设计、数据、Stata 分析、稳健性、写作与发布放在一个连续工作台中。每个阶段由专属智能体协助，但关键学术判断始终由人决定。

01 · OVERVIEW

这不是“自动写论文”，而是科研协作与治理平台

平台的价值不是替研究者做决定，而是让每个决定有证据、有版本、有检查、有负责人。即使不懂技术，也可以按页面上的阶段、待决定项和审批门推进。

A · 找问题

先查已有研究

围绕候选课题形成可复核检索、相关研究报告、研究流派和真正仍未解决的问题。

B · 定设计

把假设说清楚

比较主设计和备选设计，明确 estimand、识别假设、失败规则与未采用理由。

C · 做分析

计划先于运行

先冻结分析计划，再生成和审阅 do-file；正式 Stata 运行必须得到人工批准。

D · 可交付

正文仍由人掌控

智能体内容先预览，人工确认后才能同步到正文；同步后仍可修改并保留来源。

不可委托原则

课题选择、理论取舍、方法风险、数据许可、正式运行、失败结果解释、核心主张和最终发布，不能由智能体自行批准。

02 · START

第一次使用：六步建立一个可推进课题

从顶部“当前项目”进入项目中心，或选择“创建新课题”。项目保存后会出现在项目列表，并从 S0 开始工作。

创建项目

填写课题名称、学科、初始问题、研究对象、样本窗口、关键词与候选数据源。

人工确认：问题边界与负责人

与 Topic Agent 对话

让智能体缩小范围、检索近似研究并形成三个可证伪的问题版本。

人工确认：选题是否继续

编辑阶段草稿

点击“打开当前草稿”，直接修改摘要、正文、证据说明、决定、风险和交接字段。

人工确认：内容是否准确

运行一致性检查

检查缺失字段、证据覆盖、口径冲突、审批前置与下游影响；逐项打开并整改。

机器检查：提出问题，不替代判断

记录待决定项

在“待决定项”中接受、修改或拒绝建议，并写下理由和剩余风险。

人工确认：关键选择与风险

提交审批门

冻结当前 revision，交给指定角色会签。语义修改会生成新版本并可能使下游审批失效。

人工确认：签署并解锁下一阶段
03 · JOURNEY

S0–S9 完整科研旅程

每个阶段都有专属智能体、结构化交付、检查规则和人工决定。阶段可以回退修改，但不能绕过审批依赖。

阶段专属智能体主要工作阶段交付必须由人决定审批关系
S0 问题识别Topic Agent选题与研究空白反向检索近似课题，判断新颖性、价值与可行性。课题简报、已有研究报告、候选问题。确认边界、改写问题或暂停。G0
S1 文献综述Literature Agent证据检索与综合记录检索式、来源、纳排标准，构建论文卡和证据流派。检索协议、证据表、流派综述。决定纳入/排除与冲突处理。G1 前置
S2 理论构建Theory Agent机制与竞争解释连接构念、机制、边界条件和可区分的竞争解释。理论图、研究问题、假设草案。选择理论与贡献边界。G1 前置
S3 研究设计Design Agent主备设计比较确定 estimand、样本、主备方法、识别假设和停止条件。研究协议、设计备忘录、假设表。选择主设计并接受剩余风险。G1
S4 数据与变量Data Agent数据合同与口径登记来源、许可、变量、缺失、隐私和运行位置。数据合同、变量表、伦理清单。确认许可、代理变量与数据边界。G2
S5 识别与检验Analysis Plan Agent分析计划将每个研究问题映射到模型、公式、诊断、代码和失败动作。分析计划、模型卡、代码计划。冻结主次分析与多重检验规则。G3
S6 结果分析Stata Analyst代码与受控运行生成 do-file、运行预检、提交正式作业并收集日志和产物。do-file、日志、表图、数据签名。审代码、批准运行、选择重跑分支。G3 后运行
S7 稳健性检验Robustness Agent失败可见执行预先声明的稳健性、安慰剂、敏感性与外推检查。稳健性矩阵、失败项、复现报告。追加检验或接受失败影响。G4 前置
S8 机制与异质性Evidence Agent主张—证据图把正文主张连接到结果、机制证据、反证和适用边界。Claim-Evidence 图、解释备忘录。改写、降级或撤回主张。G4
S9 结论与政策含义Writing Agent写作与交付协作生成正文、答复信、披露、HTML 与复现发布包。论文草稿、答复信、发布包。重写、披露并批准最终发布。G5
04 · AGENTS

智能体如何与研究者共同工作

点击任一阶段的智能体即可打开统一对话工作区。左侧切换 10 个智能体，中间对话，右侧查看该阶段允许的工具、输入要求和禁止项。

01提出任务说明问题、目标、可用资产和希望的交付格式。
02工具调用智能体只调用本阶段白名单工具，并记录来源与参数。
03生成候选回答是建议或草稿，不自动成为项目事实。
04预览与确认选择同步位置、追加或替换，并勾选人工确认。
05同步后编辑写入阶段资产，保留来源、时间和同步记录，仍可人工修改。
允许

检索、提取、比较、起草

包括文献检索式建议、证据抽取、方法候选比较、Stata 代码草稿和写作重构。

需要确认

同步、运行、风险接受

正文同步前必须预览；正式运行和接受诊断失败必须由有权限的人操作。

禁止

伪造、越权、静默覆盖

不得编造引用、绕过许可、替人审批、隐藏失败结果或覆盖已批准版本。

06 · EVIDENCE

提出课题前，先形成已有相关研究报告

证据库不是简单收藏夹。每次检索保留问题、检索式、来源范围、时间、纳排理由和冲突；论文卡连接到具体主张与研究设计。

SEARCH

创建可复核检索

  • 输入主题、变量、机制或方法
  • 选择顶刊、工作论文和数据来源
  • 保留检索时间与完整条件
SCREEN

论文卡与纳排

  • 记录题名、作者、年份与稳定链接
  • 抽取问题、理论、数据、方法和发现
  • 人工确认纳入、排除及理由
SYNTHESIS

研究流派与空白

  • 区分一致结论、冲突与不可比 estimand
  • 反向检索“所谓空白”是否已被处理
  • 输出非技术人员可读的相关研究报告
引用安全规则

任何进入正文的文献必须能回到稳定来源；智能体不能根据记忆补齐作者、年份或结论。未核验来源只能标记为“待补证”，不能作为确定依据。

07 · METHODS

方法、公式与 36 条诊断规则在同一工作台

选择方法时先看研究目标、数据结构与识别假设，再看适配分数。公式卡说明符号、变量映射、条件、诊断和实现；诊断规则决定什么时候必须停止或降级结论。

METHOD

方法库

前端重点展示高频方法的深度卡；后端 28 个方法注册项是权威目录。可比较 1–3 个候选并记录未采用理由。

FORMULA

公式库

后端 47 个公式模板版本化保存。公式需绑定符号定义、变量口径、假设、诊断、代码和输出，而不是孤立展示。

DIAGNOSTIC

完整 36 条规则

支持按家族筛选、关键词检索和逐条展开。每条包含触发时点、所需证据、失败动作、等级与实现提示。

诊断家族代表检查失败时如何处理常见实现
数据质量唯一键、缺失、异常、数据签名、泄漏阻塞正式运行，回到 S4 修订数据合同。Stata isid、misstable、datasignature
面板与统计聚类层级、共线性、序列相关、横截面依赖调整推断策略并重新审批分析计划。xtserial、VIF、cluster sensitivity
DID / Event study处理前趋势、分期处理偏误、安慰剂不得继续作强因果表述，切换估计器或降级。estat ptrends、cohort-aware estimator
IV / RDD弱工具、排除限制、操纵、带宽敏感性主识别失败时切换备选设计并披露。first stage F、rdrobust、density test
匹配 / 权重重叠、平衡、极端权重、隐藏偏误限制共同支持或停止推广到无重叠人群。SMD、ESS、weight trimming、Rosenbaum bounds
SEM / 中介测量模型、拟合、间接效应、共同方法偏差不支持测量结构时不得解释路径系数。CFA、bootstrap indirect effect、fit indices
优化与运营不可行约束、MIP gap、鲁棒半径、情景稳定禁止把当前最好解报告为已证明最优。IIS、best bound、VSS/EVPI、样本外压力测试
因果机器学习交叉拟合、校准、重叠、策略样本外价值未通过 holdout 验证时不得输出确定性分群政策。cross-fitting、honest split、policy value

  • 警告：必须说明处理与剩余风险
  • 记录：保留证据与参数，便于复现
  • 规则可加入 S5–S7 检查清单
08 · STATA

Stata 从代码草稿到正式运行的受控流程

Runs 工作区包括分析计划、Do-file、运行前检查、正式运行和结果审阅。批准前可以编辑代码，但正式运行需要 G3 通过、数据签名一致且检查无阻塞。

01计划映射研究问题 → 模型 → 公式 → 诊断 → 输出。
02生成 do-file固定 Stata 版本、路径、随机种子与输出名称。
03运行前检查语法、变量、许可、数据签名和 G3 状态。
04人工批准运行记录批准人、代码哈希、环境与参数。
05结果审阅日志、表图、警告、失败项和复现信息一起交付。

set more off
use "input/firm_panel.dta", clear
datasignature

  fe vce(cluster firm_id)

collect export "output/main_results.xlsx", replace
安全边界

Stata Runner 应在隔离环境执行，只挂载批准的数据与输出目录；禁用未批准的网络访问和任意系统命令。每次作业保留 do-file、日志、数据签名、镜像或 Stata 版本、返回码与产物哈希。

12 · FAQ

常见问题与处理方式

如果界面状态与预期不一致，先查看当前项目、阶段、revision 和审批前置；不要通过重复点击绕过阻塞。

为什么诊断规则显示 36，但筛选后数量变少？
规则库共有 36 条。顶部“当前显示 X / 36”反映关键词和家族筛选结果。点击“清除筛选”即可恢复全部规则；每条都可以展开查看触发条件、证据、失败动作与实现提示。
为什么某些资产不能编辑？
审批中的确定 revision 和已批准快照是只读的。返回工作草稿或创建新修订后才能修改；修改可能使受影响审批失效，这是为了保证审批对象不会被静默替换。
为什么正式 Stata 运行按钮被锁定？
通常是 G3 尚未批准、运行前检查存在阻塞、数据签名变化或项目尚未推进到 S6。打开运行前检查与 G3 审批资产，逐项处理后再提交人工批准。
智能体的回答如何进入交付正文？
在对话中选择“同步到阶段资产”，指定目标字段与追加/替换方式，预览内容并勾选人工确认。同步后内容仍可在“打开当前草稿”中修改，且保留对话来源和同步时间。
如何修改界面颜色和风格？
点击右上角用户头像，选择“界面偏好”，在石墨极简、冷蓝研究和论文纸张中切换。选择即时生效并保存在当前浏览器。
后端暂时连接不上，会不会丢失页面操作？
界面会显示“前端演示数据模式”。当前实现允许部分前端操作继续演示，但生产使用前必须确认后端同步成功；关键资产、审批和正式运行不能依赖仅浏览器状态。
发现引用或结果不一致怎么办？
不要直接删除冲突。打开对应证据卡或运行产物，修正来源和口径，重新运行一致性检查，并在人工决定中记录处理理由。已进入核心主张的内容需在 G4 重新审核。
“查看”“展开”按钮应该发生什么？
所有查看类按钮都应打开相应详情、深层工作区或状态面板，不能只显示提示。资产摘要的六个“展开”入口会打开可阅读、草稿可编辑的章节详情。
