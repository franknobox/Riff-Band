# AI4MS 产品定义

## 1. 产品定位

AI4MS 是面向管理科学研究的本地优先 AI 科研工作台。它把问题澄清、文献检索、理论构建、研究设计、数据治理、统计执行、稳健性审查、证据组织和成果交付放在一个可追溯项目中。

产品借鉴玻尔等一体化科研工作台的使用形态，但不做通用聊天壳。核心差异是：

- 以管理科学的研究设计、方法假设、数据许可和 Stata 工作流为中心；
- AI 只生成草稿和建议，关键阶段由人批准；
- 文献、数据、代码、运行结果、主张和报告通过 ID、revision 与 hash 关联；
- 失败、反证、限制和未知必须保留，不能由写作模型隐藏；
- 最终交付包含浏览器 GUI、HTML 可视化报告和可复现研究包。

## 2. 目标用户

- 需要完成实证、因果、预测、优化或混合研究的管理科学研究者；
- 负责研究设计、方法审核、数据合规或复现检查的导师和团队成员；
- 需要快速理解项目状态、证据边界与下一步行动的科研协作者。

## 3. S0-S9 工作流

| 阶段 | 核心任务 | 主要产物 | 人工控制 |
|---|---|---|---|
| S0 问题识别 | 澄清对象、问题边界、已有认识与候选空白 | `TopicBrief` | G0 确认选题边界 |
| S1 文献综述 | 多源检索、去重、筛选、流派与覆盖限制 | `RelatedResearchReport` | 核验论文与检索范围 |
| S2 理论构建 | 理论机制、研究问题、竞争解释与可证伪命题 | `TheoryModel` | 选择理论与贡献边界 |
| S3 研究设计 | 分析单位、主备设计、假设、风险和停止条件 | `ResearchProtocol` | G1 批准设计 |
| S4 数据与变量 | 数据来源、变量口径、许可、隐私与质量 | `DataContract` | G2 批准数据边界 |
| S5 识别与检验 | estimand、模型、诊断、分析步骤和代码计划 | `AnalysisPlan` | G3 冻结计划与代码 |
| S6 结果分析 | Runner、日志、表图、结构化结果和复现信息 | `RunArtifact` | 人工启动、取消和重跑 |
| S7 稳健性检验 | 替代口径、样本、模型、安慰剂与失败检验 | `RobustnessReport` | 接受影响或追加检验 |
| S8 机制与异质性 | Claim-Evidence、机制、异质性、反证和限制 | `ClaimEvidence` | G4 批准解释边界 |
| S9 结论与政策含义 | 结论、政策含义、引用、报告和发布包 | `ResearchPackage` | G5 批准发布 |

阶段状态统一为 `not_started / in_progress / needs_review / approved / blocked`。上游关键内容变化会使下游批准失效；AI 和 service account 不能成为批准人。

## 4. 核心产品能力

### 项目与版本

- 创建并持久化研究项目；
- 每个阶段保存不可变 revision、内容 hash、作者类型和变更理由；
- 人工批准、退回和阻塞决定进入审计记录；
- 容器重启后项目、审批、资产和报告仍可恢复。

### 文献与科研建议

- 多来源检索、标准化、去重和快照；
- 论文卡、研究流派、共识、争议、反向检索和覆盖限制；
- 从证据生成研究空白、理论候选、方法建议和下一步行动；
- 不把“本次未检索到”写成“不存在”。

### AOrchestra 编排

S0-S1 与 S7-S8 接入基于论文 **AOrchestra: Automating Sub-Agent Creation for Agentic Orchestration** 的动态 SubAgent 编排。

- S0-S1 用于边界澄清、检索侦察、反向检索和综述；
- S7-S8 用于稳健性、负结果、Claim-Evidence 和过度主张审查；
- SubAgent 按阶段获得最小工具权限；
- 输出必须通过 Pydantic 契约、ID 白名单和阶段门禁后才能保存。

### 数据与 Stata

- 上传 `.dta`，登记 SHA-256、Stata 格式和变量元信息；
- G3 后执行真实 Preflight；
- Docker 工作台通过配对令牌连接研究者本机合法 Stata；
- 后台任务支持状态查询、超时、取消和重跑；
- Result Bundle 回收机器可读结果、日志、数据签名、表图和 artifact hash；
- `.dta`、Stata 安装文件和许可证不进入返回包或 Docker 镜像。

### HTML 可视化报告

HTML 报告是正式产品输出，不是装饰性导出。报告应让审核者从结论回到论文、数据、Run、Claim-Evidence 和审批记录。当前 S9 可确定性生成 HTML 报告、manifest 和 ZIP 研究包。

## 5. 多学科泛用性

产品首先服务管理科学，但通过 `DomainProfile`、方法库、公式库、数据源库和阶段输出契约保持可扩展性。优化方向包括：

- 避免通信、医学或其他高频领域术语污染管理科学课题；
- 方法推荐由研究目标、数据形状和关键假设驱动；
- 领域知识与通用 Agent Runtime 解耦；
- 新学科通过领域画像和注册表扩展，不复制整套流水线。

## 6. 可信边界

- 不保证研究绝对原创；
- 不绕过论文、数据和商业软件许可；
- 不自动把相关性、显著性或预测准确率写成因果贡献；
- 不允许 AI 自批或绕过 Gate 启动正式分析；
- 不允许手工修改正式运行数值；
- 受限数据默认不发送给外部模型；
- 失败运行、负结果、冲突证据和未知必须可见。

## 7. 当前实现与已知缺口

当前已经具备 FastAPI、SQLite、S0-S9 状态机、revision/approval、阶段模型生成、多源检索、知识注册表、AOrchestra、Stata BYOL Runner、Claim-Evidence 约束、HTML/ZIP 导出、Next.js GUI 和 Docker 单入口。

仍需继续收口的部分：

- 证据库、智能体建议和部分深层页面仍存在展示型数据或本地交互；
- 前端主页面和全局样式文件过大，需要按工作区拆分；
- 当前后台任务适用于单进程比赛部署，尚不支持多实例调度和重启续跑；
- 真实 Docker + 合法 Stata 的端到端演示必须在具备相应环境的机器完成。

## 8. 比赛验收

- Docker 启动后通过浏览器直接进入完整工作台；
- 一个项目可从 S0 流转到 S9，并在重启后恢复；
- 文献、数据、Run、Claim 和报告具有真实来源或明确未知状态；
- 无模型、无网络或无 Stata 时准确显示阻塞，不伪装成功；
- HTML 报告和 ZIP 研究包可下载；
- 镜像和日志不包含 API Key、Stata 许可证或受限数据。
