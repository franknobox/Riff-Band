# 玻尔（Bohrium）公开能力对标与 AI4MS 产品取舍

版本：0.2  
资料快照：2026-07-16

## 1. 对标口径

本文件只依据玻尔、深势科技和高校图书馆公开页面，不测试登录后功能，也不推测其内部技术。公开页面中的资源量和用户量属于厂商披露，本文不作独立审计。

## 2. 玻尔公开展示的成果

玻尔把产品描述为从科研问题出发，连接论文检索、进展追踪、文献阅读、综述/报告和科研图示的完整任务流。其公开产品页强调：

- 从自然语言提问中厘清关键词、研究脉络与前沿问题；
- 在回答中呈现参考文献、引用依据和论文来源；
- 把结论继续整理成综述初稿、研究报告或图示；
- 用关键词、期刊或学者订阅追踪最新进展；
- 将检索、对话、阅读笔记和 AI 总结归入个人知识库；
- 连接论文、学者、期刊、课程、Notebook、科研 Apps 和计算资源。

玻尔产品介绍页在 2026-07-16 显示的厂商口径包括 2.0 亿+论文资源、2000 万+学者信息、14 万+期刊资源和 450 万+全球科研用户。华东师范大学图书馆 2025 年的试用说明还列出科学导航、知识库、文献阅读、订阅、课程、Notebook、Apps、计算和科研助手等模块。上述数字和功能应视为公开宣传/试用说明快照，正式竞品研究应进行登录实测和用户访谈。

## 3. 借鉴—增强—暂缓

| 决策 | 能力 | AI4MS 的处理 |
|---|---|---|
| 借鉴 | 自然语言问题入口 | 用简短问答形成可批准的 TopicBrief |
| 借鉴 | 文献证据随答案呈现 | 所有结论绑定 paper/evidence ID 与定位 |
| 借鉴 | 检索到调研/综述/报告连续工作流 | 形成版本化 RelatedResearchReport，并可进入 Research Protocol |
| 借鉴 | 订阅、发现和个人知识资产 | 建 Watchlist，增量结果回到项目知识库 |
| 借鉴 | 搜索、阅读、写作和计算的统一入口 | Web/CLI/MCP 共用项目和资产层 |
| 增强 | 管科研究设计 | 区分因果、实证、解析/优化、预测、行为/定性、综述/设计科学 |
| 增强 | 可审计检索 | 保存数据库、查询、日期、命中、去重、纳排与失败日志 |
| 增强 | 研究空白判断 | 六类 Gap + 反向查询 + 覆盖限制 + 人工批准 |
| 增强 | 数据和方法可行性 | 同时检查变量可观测性、许可、识别假设、计算规模和备选方案 |
| 增强 | Claim–Evidence–Assumption | 结论、反证、假设、运行和产物双向追踪 |
| 增强 | 可复现性 | 协议版本、代码、环境、输入输出哈希和复现包 |
| 暂缓 | 海量通用课程/应用市场 | 不是管科科研 MVP 的核心验证对象 |
| 暂缓 | 自建大规模 CPU/GPU 云 | 初期使用受控容器和外部/机构算力适配 |
| 暂缓 | 通用科研绘图工具集 | 先保证证据、方法、数据和报告可信 |

## 4. AI4MS 的清晰定位

AI4MS 不以“资源量比玻尔更多”为目标。更合理的差异化是：

> 玻尔启发了“从问题到科研产出”的一体化体验；AI4MS 聚焦管理科学，把选题、既有研究、理论、数据、识别、模型、稳健性和主张做成可审计、可批准、可复现的研究协议。

## 5. 建议的竞品实测任务

后续安排 5 名研究生和 3 名教师，以相同的 6 个课题在玻尔、通用大模型、Google Scholar/传统数据库和 AI4MS 原型上完成：

1. 找到 10 篇最相关论文；
2. 识别三条研究流派；
3. 找到一个结论冲突；
4. 判断一个候选研究空白；
5. 给出可用数据和方法；
6. 输出带来源的相关研究报告。

记录耗时、有效论文比例、漏掉的种子论文、虚构/错误引用、空白误判、方法错配、人工修改量和用户信任。竞品的 UI 体验可借鉴，研究有效性必须用同一专家金标比较。
