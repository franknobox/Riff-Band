# AI4MS：面向管理科学研究的 AI for Science 平台 PRD

版本：0.3（增加 Stata、全程人工编辑/审批与分阶段协作智能体）  
日期：2026-07-16

## 1. 一句话定位

AI4MS 是一个把**研究问题、文献证据、数据许可、方法假设、计算运行和论文主张**连接成可追踪工作流的管理科学科研平台。

它不是“自动生成论文”的聊天机器人，而是研究设计与复现基础设施：帮助研究者更快提出可检验问题、选择合适方法、执行诊断和稳健性检验，并让每个结论能回到证据、代码、数据版本与假设。

## 2. 为什么现在做

当前科研工具链割裂：文献在检索器和 Zotero，研究设计在聊天记录或 Word，数据在本地/机构库，模型在 notebook，结果在临时表格，写作在 LaTeX/Word。LLM 提高了局部速度，却放大了三个风险：虚构文献、方法与问题错配、不可复现。

Riff-Band 已经具备多 Agent 编排、固定研究流水线、学术检索工具、JSONL 研究资产和基本质量门禁，可作为 Orchestration Kernel。产品机会不是推倒重来，而是把它从“摘要级文献综述流水线”升级为“研究协议驱动的全链路科研平台”。

## 3. 目标用户与核心任务

| 用户 | 核心任务 | 当前痛点 | 产品承诺 |
|---|---|---|---|
| 硕博研究生 | 从选题走到可执行设计 | 不知道下一步、方法碎片化、反复返工 | 每阶段有模板、门禁和下一步建议 |
| 管科教师/PI | 管理多个课题和学生 | 很难审计证据、代码和口径 | 一屏看到协议、风险、证据与复现状态 |
| 科研助理/实验室 | 检索、编码、清洗、复现 | 重复劳动、交接困难 | 可复用连接器、卡片、运行与审计轨迹 |
| 企业/政策研究团队 | 快速做可信决策研究 | 速度与严谨性冲突 | 可追踪结论、许可边界和可执行建议 |
| 方法开发者 | 沉淀模型与模板 | 公式、代码、适用条件散落 | 可版本化 Method/Formula/Benchmark 卡片 |

## 4. 产品原则

1. **Protocol-first**：先冻结问题、设计和主要指标，再运行分析。
2. **Evidence-first**：任何重要 claim 都必须指向来源或运行产物。
3. **Branch, then converge**：统一阶段，不强行统一方法。
4. **Deterministic controls**：引用核验、统计、求解、哈希和规则门禁尽量用确定性工具。
5. **Human approval by default**：选题、设计、数据、分析代码、结果主张和最终发布必须人工确认；Agent 永远不能审批。
6. **Reproducibility as a feature**：版本、环境、随机种子、输入/输出哈希是一等数据。
7. **Licensing-aware**：平台知道“能访问”不等于“能上传、处理或再分发”。
8. **Editable, not silent**：智能体只生成可编辑草案和 patch；用户修改留版本，批准版本不被静默覆盖。
9. **One principal agent per stage**：每个科研阶段有一个主协作智能体，但阶段所有权和最终决定属于用户。

## 5. 产品形态

- **Web Research Workbench（主产品）**：面向研究者和团队的图形工作台。
- **CLI（高级用户）**：延续 Riff-Band 的交互和批处理能力。
- **MCP/API（集成层）**：供 Codex、Claude Code、IDE、Zotero 与机构系统调用。
- **可复现执行器（服务端或本地）**：Python、Stata、R 与优化求解适配；敏感数据和商业软件优先本地/机构 Runner。

## 7. 关键功能需求

### F-01 项目与研究协议

- 新建项目时必须填写现象、问题、研究目标、分析单位、时间、地域和可证伪条件。
- 根据目标推荐五条方法泳道，但展示至少两个备选设计和错配风险。
- 研究设计门必须由用户批准；批准后生成版本化 `research_protocol.json`。
- 任何关键字段修改都产生新版本和变更原因，不静默覆盖。

验收：没有 `human_approved=true` 的设计不得启动主分析。

### F-01A 课题侦察与已有研究报告

- 用户可用一句自然语言描述想法；系统追问研究对象、分析单位、目标、时间、地域、核心概念、已有数据和种子论文，并生成可人工批准的 TopicBrief。
- 执行地平线扫描、系统扩展和空白反向复核三层检索；覆盖经典研究、近年进展、相邻学科、不同术语和反向证据。
- 按“研究问题—理论—数据—方法—结论—局限”结构化核心论文，形成研究流派、时间演化、共识、争议和未知。
- 将研究空白拆为理论、情境、数据、方法、时间和实践六类；“未检索到”不得改写成“无人研究”。
- 为每个候选空白保留支持证据、反向查询、覆盖限制、置信度和人工批准状态。
- 输出 2—3 张候选课题卡，展示新颖性、重要性、可行性和可证伪性评分及依据，并列出最危险的相近论文、数据要求、首选/备选方法和停止条件。
- 生成“决策摘要 + 证据附录”两层相关研究报告，支持 Markdown/DOCX/JSON 导出；报告批准后可生成 Research Protocol v1。
- 用户可把批准的检索式、关键词、期刊或学者加入 Watchlist，后续增量更新进入同一项目。

验收：报告中虚构文献为 0；核心综合结论 100% 可回溯；每个 `supported_gap` 均有反向查询和人工批准；批准前不得使用“首个/无人研究/完全空白”等绝对新颖性表述。

详细规格见 `TOPIC_SCOUT_AND_RELATED_RESEARCH_REPORT.md`。

### F-02 文献检索与筛选

- 支持 OpenAlex、Crossref、Semantic Scholar、arXiv，后续接 Unpaywall 与机构全文。
- 检索协议保存数据库、检索式、时间、过滤器、结果数和快照。
- 多源结果做 DOI、题名、作者、年份的分层去重，而不是只取第一个成功后端。
- 具有纳入/排除、原因、双人复核、冲突解决和 PRISMA 导出。
- 引用量必须显示来源与快照日期，不作为质量分的唯一输入。

验收：随机抽取 100 条，DOI/题名去重准确率 ≥98%；不存在的 DOI 不得进入参考文献。

### F-03 论文结构化卡片

- 抽取研究问题、理论、数据源、样本、变量、方法、核心公式、结果、稳健性、局限和证据定位。
- 每个字段记录来源层级：metadata / abstract / full text / human verified。
- 抽取结果与 PDF 页码、章节或摘要句子绑定；低置信字段进入人工队列。
- 支持按模板导出为 CSV/JSON/BibTeX。

验收：人工验证集上关键字段宏平均准确率 ≥85%，引用/DOI ≥99%。

### F-04 Method Studio

- 按研究目标、数据形态、识别条件和计算规模筛选方法。
- 每张方法卡包含适用问题、最小数据、核心假设、流程、诊断、稳健性、公式、代码和常见失败。
- 推荐结果必须给出“选择理由、不能解决什么、需要验证什么、替代方案”。
- 支持团队创建私有方法卡和版本。

验收：方法推荐无法满足关键假设时必须返回“阻塞/需要更多信息”，不能硬给答案。

### F-05 Data Hub

- 数据源卡显示地域、访问、成本、接口、许可、PII、典型实体与连接器优先级。
- 项目中的每个数据集必须有 Data Contract：快照、单位、时间、变量、连接键、许可、质量检查、存储策略。
- 敏感数据默认本地执行；平台只保存元数据、哈希和批准后的聚合结果。
- 不支持自动绕过付费、登录、robots 或许可限制。

验收：license_status 不是 `cleared/not_applicable` 时，不得进入远程执行。

### F-06 Experiment Lab

- 从 Method/Formula 卡生成可编辑 notebook 或脚本骨架。
- 运行记录代码 commit、lockfile、容器、参数、随机种子、输入输出哈希和日志。
- 支持 Python；Stata 通过受控 batch/local Runner 进入首批统计执行能力；R 与商业求解器按适配器后续接入。
- 长任务可取消、重试、恢复；同一 manifest 可复现运行。

验收：固定输入与种子下，基准任务 95% 能在干净环境复现规定容差内结果。

### F-06A Stata 可复现分析工作台

- 从已批准的 Analysis Plan、MethodCard、FormulaCard 和 Data Contract 生成可编辑 do-file 草案；AI 只能提交 patch，用户可逐段接受、修改或拒绝。
- G3 批准对象必须绑定分析计划 revision、do-file SHA-256、数据合同版本、Stata Runner 和环境/ado manifest；hash 不一致不得启动主分析。
- 支持用户/机构自带许可的 local/institution Runner；平台不分发 Stata 安装包、许可证或任意社区 ado。
- MVP 提供数据审计、OLS、面板 FE 和 DiD；后续提供 IV、RDD、生存、SEM、survey/MI、时序和元分析。
- batch run 保存 SMCL/text log、退出码、Stata 版本/edition、`adopath/which`、`datasignature`、输入输出 hash、表图、DTA/STER 和完整血缘。
- 默认无网络并阻塞外部进程、动态 ado 安装、未批准 Python/Java、越界路径和原始数据覆盖；例外必须人工批准。
- 原始日志、运行数值和表图产物不可手改；用户可以修改解释，数值变化必须来自新 Run。

验收：A31—A35 通过；固定输入/代码/环境重放一致；危险命令、许可席位不足、无 G3 或过期 revision 的运行全部被拒绝。

详细规格见 `STATA_ANALYSIS_WORKBENCH.md`。

### F-07 Robustness Center

- 根据泳道生成专属威胁与检验：因果的预趋势/安慰剂，优化的 gap/压力测试，ML 的泄漏/外部测试，实验的功效/流失，定性的负例/编码一致性。
- 以“计划—运行—结果—影响”矩阵呈现，不只生成文字建议。
- 任何失败检验都必须影响 claim 的状态或置信等级。

验收：核心 claim 不允许在关联检验失败时保持 `high confidence`。

### F-08 Evidence Graph

- Claim、Evidence、Assumption、Run 和 Artifact 是独立对象。
- 每个核心 claim 至少有一个证据；证据可支持、反驳或限定。
- 写作只能引用已批准或显式标为 tentative 的 claim。
- 图形界面后置，MVP 先实现可筛选表与双向链接。

验收：成稿中 100% 的核心结论可回溯到 evidence ID 和 source/run。

### F-09 Writing & Review

- 从批准的框架、claim、图表和参考文献生成大纲与段落。
- 不允许模型凭空增加数值、样本或引文；未知字段保留占位/问题。
- 可模拟方法审稿、领域审稿、复现审稿与数据伦理审稿。
- 导出 Markdown、LaTeX、DOCX/BibTeX；保留引用键和证据链接。

验收：引用审计零虚构；数值与表图一致性检查通过。

### F-10 分阶段智能体、人工编辑与审批

- S0—S9 每个科研阶段配置一个用户可见的主协作智能体：选题、文献、理论、设计、数据、分析计划、Stata/计算、稳健性、证据、写作。
- 智能体输出默认 `machine_draft`，通过结构化 patch 修改；用户可直接编辑、逐项接受/拒绝、评论、回滚和从批准版本分叉。
- 实行 G0 选题、G1 理论/设计、G2 数据/伦理/许可、G3 分析计划/代码、G4 结果/Claim、G5 成稿/发布六个人工 Gate。
- 批准绑定明确的 revision/hash、批准人、角色、检查清单和时间；Agent、无权限角色和过期 revision 均不能批准。
- 上游语义修改按依赖矩阵自动失效下游 Gate，但不删除旧审批和审计记录。
- 单人项目可显式使用 single-reviewer；团队项目默认 four-eyes，高风险对象支持多人会签。
- 用户只面对一个阶段主智能体；内部 helper 的分歧、证据和失败由主智能体整理后呈现。

验收：A36—A40 通过；静默修改和 Agent 自批为 0；用户能在每阶段说明 AI 做了什么、自己改了什么、谁批准了什么。

详细规格见 `HUMAN_APPROVAL_AND_EDITING.md` 与 `STAGE_AGENT_COLLABORATION.md`。

## 9. MVP 边界（首个 8—10 周）

MVP 要跑通的闭环：

`研究想法 → S0 Topic Agent/已有研究报告 → G0 → 理论与设计协作 → G1 → 数据/伦理 → G2 → 分析计划与 do-file → G3 → Python/Stata Run → 稳健性 → Claim → G4 → 写作/复现包 → G5`

MVP 暂不做：

- 全功能 JupyterHub/RStudio/Stata 云桌面；先运行受控 Python 模板和 BYOL Stata batch/local Runner；
- 通用企业级数据湖；先做 Data Contract 和 5—8 个开放连接器；
- Neo4j 级图数据库；先在 PostgreSQL 中用节点/边表；
- 完全自治选题、分析和发文；G0—G5 必须由人批准；
- 自动抓取付费全文或绕过机构授权。

## 10. 成功指标

### 北极星指标

**从研究问题冻结到“可复现分析计划 + 可追踪核心 claims”的中位时间**。

### 质量指标

- DOI/引文准确率 ≥99%；
- 核心 claim 证据覆盖率 100%；
- 关键方法字段人工复核准确率 ≥85%，逐季提升；
- 基准复现通过率 ≥95%；
- 方法/数据许可阻塞能被正确识别，不以生成文本掩盖；
- 用户对 AI 建议的修改原因可归类，持续降低“方法错配”比例。

### 业务/使用指标

- 试点项目 30 日内至少完成一次设计门和一次复现检查；
- 团队复用 Method/Data 卡的比例；
- 从搜索结果到纳入文献的有效率；
- 专家种子论文 Recall@50、错误空白判断率和候选课题进入协议的转化率；
- 从一句研究想法到首份可审阅相关研究报告的中位时间；
- 每项目人工节省时间，但不得以牺牲质量门禁为代价。
- Stata 基准任务重放通过率、do-file 人工修改率与危险命令阻塞率；
- G0—G5 首次通过率、changes-requested 原因、失效后正确重审率和审批等待时间；
- 各阶段 Agent patch 的接受/修改/拒绝率与跨阶段退回率。

## 11. 试点建议

选择 3 类、每类 2 个真实课题：

1. 面板/因果：企业 AI 采用对绩效或组织流程的影响；
2. 优化/运营：低碳物流、库存或平台供应链；
3. 预测/计算：文本、时序或网络风险。

每个课题指定一名研究者、一名导师/PI 和一名方法审核者；涉及受限数据时增加 Data Steward。至少 3 个课题使用 Stata Runner。比较“原流程 vs AI4MS”在耗时、返工、引用错误、设计缺陷、人工审批完整性和复现率上的差异。
